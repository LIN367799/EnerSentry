## 1. 引言

### 1.1 编写目的

本《软件需求规格说明书》（SRS）是对 EnerSentry 储能电站电池簇高频采集与智能监控上位机系统的**正式需求定义**。其目的在于：

- 为系统设计、开发、测试提供**可追踪、可验证**的需求基线；
- 明确系统**功能边界**与**性能指标**，消除需求歧义；
- 为验收测试与质量评审提供**逐条对照依据**；
- 作为项目蓝图（《EnerSentry-工业上位机实战项目蓝图 v2.0》）与后续技术设计文档之间的**衔接桥梁**。

**预期读者**：系统开发人员、测试工程师、项目评审人员、面试技术面试官。

### 1.2 文档范围

本文件定义 EnerSentry 上位机系统的全部软件需求，包括：

- 7 大功能模块的详细功能需求（电站总览、实时曲线、告警中心、历史趋势、参数配置、通信诊断、设备模拟器）；
- 本地控制（SBO）、权限管理（RBAC）、数据生命周期管理等横向能力需求；
- 性能、可靠性、安全性、可用性等非功能需求；
- 外部接口需求（用户界面、硬件、通信、软件接口）；
- 数据存储与导出需求。

**不包含**：系统内部架构设计、并发模型、协议引擎实现细节、UI 视觉设计稿——这些将在后续《概要设计说明书》与《详细设计说明书》中展开。

## 2. 总体描述

### 2.1 产品概述

EnerSentry 是一台运行于储能电站现场的**站端监控上位机 / 本地 SCADA-HMI 软件**。它运行在电站工控机或监控电脑上，负责将 BMS、PCS、关口电表及辅机设备上报的实时数据，经过协议解析、数据组织后，以总览图、实时曲线、告警和报表的形式呈现给运维人员，并提供本地历史数据存储与事故回溯能力。

**产品定位**：

| 维度 | 说明 |
|------|------|
| 系统角色 | 储能电站站端监控上位机，位于设备层之上、云端与 EMS 之下 |
| 控制能力 | 以**只读监视为主**；具备本地紧急控制能力，严格遵循 SBO 双重确认与权限校验 |
| 部署形态 | 单机部署，本地优先，断网可用、掉电不丢 |
| 对标产品 | 工业组态软件 KingSCADA / iFIX / WinCC 的站端监控能力 |

### 2.2 产品功能概览

系统包含 7 大功能模块与 3 项横向能力，如下所示：

```
┌─────────────────────────────────────────────────────────────────┐
│                        EnerSentry 系统功能全景                      │
├──────────┬──────────┬──────────┬──────────┬──────────────────────┤
│ ① 电站总览│② 实时曲线 │③ 告警中心 │④ 历史趋势 │   ⑤ 参数配置          │
├──────────┴──────────┴──────────┴──────────┴──────────────────────┤
│ ⑥ 通信诊断  │  ⑦ 设备模拟器（独立程序 + 故障注入控制台）              │
├──────────────────────────────────────────────────────────────────┤
│ 横向能力：⑧ 本地控制(SBO) │ ⑨ RBAC权限管理 │ ⑩ 数据生命周期管理      │
└──────────────────────────────────────────────────────────────────┘
```

| 模块 | 核心职责 |
|------|---------|
| ① 电站总览 | 站→簇→包三级钻取，SOC/温度/电压概览，异常色块可视化 |
| ② 实时曲线 | 多通道曲线滚动刷新，盯盘与瞬时异常观察 |
| ③ 告警中心 | 三级告警分级、声光提示、确认闭环、告警历史、黑匣子快照关联 |
| ④ 历史趋势 | 任意时间段查询、曲线缩放回放、CSV 导出 |
| ⑤ 参数配置 | 点表驱动配置（设备/从站/寄存器/轮询周期/阈值），不硬编码 |
| ⑥ 通信诊断 | 链路状态/通信质量统计/CRC错误率/往返时延实时监控 |
| ⑦ 设备模拟器 | 独立程序模拟整站设备，故障注入控制台 |
| ⑧ 本地控制(SBO) | 紧急控制（排风/液冷/复位/急停），SBO 双重确认 + 留痕 |
| ⑨ RBAC权限管理 | 操作员/工程师/管理员三级权限，操作留痕审计 |
| ⑩ 数据生命周期 | L1 快照库 + L2 降采样历史库分级持久化 |

### 2.3 用户特征与角色

| 角色 | 使用场景 | 技术背景 | 关心什么 |
|------|---------|---------|---------|
| **电站运维工程师** | 7×24 值守，日常巡检、告警处理、周报导出 | 熟悉电站设备，非软件开发者 | 信息密度高、响应快、告警不漏 |
| **现场调试/集成工程师** | 上线前联调、点表配置、链路调试 | 熟悉 Modbus 协议与设备点表 | 配置灵活、诊断清晰、模拟器可用 |
| **储能系统集成/EMS 工程师** | 长期趋势分析、电池一致性评估 | 熟悉电池特性与数据分析 | 历史查询快、导出方便、数据准确 |
| **管理员** | 用户管理、系统配置、权限分配 | 系统管理员 | 权限可控、操作可审计 |

| A-05 | 现场工控机性能达标 | 运行环境满足 2.4.1 最低配置要求 |

### 3.2 硬件接口

#### 3.2.1 串行通信接口

| 编号 | 需求 | 优先级 |
|------|------|--------|
| HW-01 | 支持标准 RS485 串口通信（通过物理串口或 USB 转串口适配器） | P0 |
| HW-02 | 串口参数可配置：波特率（9600/19200/38400/115200 等）、数据位、停止位、校验位 | P0 |
| HW-03 | 支持多串口同时工作（通过多串口卡扩展，至少 4 路并行） | P0 |
| HW-04 | 支持虚拟串口（com0com / socat），用于与设备模拟器联调 | P0 |

#### 3.2.2 CAN 总线接口

| 编号 | 需求 | 优先级 |
|------|------|--------|
| HW-05 | 架构预留 CAN 总线直连接口：Linux 平台通过 SocketCAN，Windows 平台通过周立功（ZLG）CAN 卡 SDK | P1 |
| HW-06 | CAN 接口支持 CANopen / SAE J1939 帧格式解析扩展（首发版本为架构预留，非全功能实现） | P2 |

#### 3.2.3 网络接口

| 编号 | 需求 | 优先级 |
|------|------|--------|
| HW-07 | 支持标准以太网（TCP/IP），千兆网口 | P0 |
| HW-08 | 支持多网卡环境下的接口绑定配置 | P1 |

### 3.3 通信接口

#### 3.3.1 Modbus RTU

| 编号 | 需求 | 优先级 |
|------|------|--------|
| COMM-01 | 支持 Modbus RTU 协议（基于 TIA-485 / RS485 物理层），遵循 Modbus over Serial Line 规范 | P0 |
| COMM-02 | 支持功能码：FC01（读线圈）、FC02（读离散输入）、FC03（读保持寄存器）、FC04（读输入寄存器）、FC05/06（写单线圈/寄存器）、FC0F/10（写多线圈/寄存器） | P0 |
| COMM-03 | RTU 帧的 CRC-16 校验完整实现，对校验失败的帧丢弃并计数 | P0 |
| COMM-04 | 支持多从站轮询调度，轮询周期可按设备/从站独立配置 | P0 |
| COMM-05 | 半双工总线调度：同一总线上严格串行请求-等待-响应，不并发冲突 | P0 |

#### 3.3.2 Modbus TCP

| 编号 | 需求 | 优先级 |
|------|------|--------|
| COMM-06 | 支持 Modbus TCP 协议，遵循 MBAP 头规范（Transaction ID + Protocol ID + Length + Unit ID） | P0 |
| COMM-07 | 支持 TCP 多连接并行（不同设备/从站可同时请求，不受半双工限制） | P0 |
| COMM-08 | 支持功能码与 RTU 一致（COMM-02） | P0 |
| COMM-09 | TCP 连接自动重连：断线后按指数退避策略重连，重连间隔 1s→2s→4s→...→30s 封顶 | P0 |

#### 3.3.3 CAN 总线（预留扩展）

| 编号 | 需求 | 优先级 |
|------|------|--------|
| COMM-10 | 协议层预留 CAN 帧解析接口，支持后续扩展 CANopen / SAE J1939 报文解析 | P1 |
| COMM-11 | 支持 CAN 转 Modbus 网关透明接入（此时 CAN 设备经网关转为 Modbus 从站，系统无需改动） | P1 |
| COMM-12 | 协议引擎层定义统一的 `IChannel` 抽象接口，隔离串口（RS485）、Socket（TCP）及 CAN 驱动的差异；上层协议解析仅依赖 `IChannel` 读写接口 | P1 |
| COMM-13 | `IChannel` 实现至少覆盖：串口通道（Windows/Linux 串口 API）、TCP 客户端通道、SocketCAN 通道（Linux）与周立功 CAN 卡通道（Windows，基于厂商 SDK） | P2 |

#### 3.3.4 通信质量统计

| 编号 | 需求 | 优先级 |
|------|------|--------|
| COMM-14 | 每条通信链路实时统计：请求总数、响应成功数、超时数、CRC 错误数、平均往返时延（RTT） | P0 |
| COMM-15 | 通信质量百分比 = 成功响应数 / 请求总数 × 100%，实时刷新 | P0 |
| COMM-16 | 链路断线/恢复事件写入操作日志，含时间戳与链路标识 | P0 |

### 3.4 软件接口

| 编号 | 需求 | 优先级 |

## 6. 数据需求

### 6.1 数据模型概述

系统处理的数据按生命周期分为三类：

| 数据类别 | 来源 | 特征 | 存储位置 |
|---------|------|------|---------|
| **实时数据** | 设备通信解析 | 高频（100ms~1s）、持续流入 | L1 快照库（内存） |
| **历史数据** | 实时数据降采样 | 低频（1s/5s 聚合）、长期保存 | L2 历史库（磁盘） |
| **事件/日志数据** | 告警/操作/通信事件 | 事件驱动、不可篡改 | L2 历史库（磁盘） |

### 6.2 数据生命周期与存储策略

```
设备字节流 → 协议解析 → 实时数据中枢
                              │
                    ┌─────────┼─────────────┐
                    ▼         ▼             ▼
              [界面呈现]  [告警判定]    [历史落库]
                    │         │             │
                    │    触发告警时       降采样聚合
                    │    锁定黑匣子       1s/5s Max/Min/Avg
                    │         │             │
                    ▼         ▼             ▼
              L1 快照库（内存）         L2 历史库（磁盘）
              · 最近1h 全量高频          · 降采样长期存储
              · 黑匣子快照(±30s)         · 保留180天
              · 滚动淘汰                 · 自动清理
```

| 层级 | 存储介质 | 保留策略 | 数据精度 | 用途 |
|------|---------|---------|---------|------|
| **L1 快照库** | 内存 | 最近 1 小时 | 100ms 原始全量 | 实时盯盘；黑匣子快照（告警前后 30s） |
| **L2 历史库** | 本地磁盘 | 180 天（可配置） | 1s/5s 降采样（Max/Min/Avg） | 长期趋势、周报回溯、一致性分析 |
| **L2 黑匣子表** | 本地磁盘 | 永久（手动清理） | 100ms 原始高频 | 事故回放 |
| **事件/日志表** | 本地磁盘 | 180 天 | 事件级 | 告警历史、操作审计、通信事件 |

### 7.5 后续设计阶段关键约束与建议

以下内容为从蓝图到 SRS 评审过程中识别的**工程关键细节**，供《概要设计说明书》《详细设计说明书》阶段重点展开。其中已能量化的部分已转为第 4/5 章正式需求，此处保留设计层面的约束与验收检查项。

#### 7.5.1 通信总线与协议引擎

| 关注点 | 设计约束 | 对应 SRS 需求 | 设计验收检查项 |
|--------|---------|--------------|----------------|
| **RS485 半双工瓶颈** | 115200 bps 典型有效吞吐约 10 KB/s；100ms 帧周期下单条 RS485 链路可承载的 Modbus 寄存器数量有限。高频 BMS 核心包优先走 Modbus TCP 或 CAN 总线 | NFR-PERF-02、NFR-PERF-11 | 概要设计给出单条 RS485 链路的最大轮询寄存器数与最大从站数计算公式；100ms 包不依赖纯 RS485 链路 |
| **IChannel 抽象** | 接入层必须抽象统一通道接口，禁止上层协议代码直接调用平台串口/CAN API；新增通道类型时不应改动协议解析代码 | COMM-12、COMM-13、NFR-PORT-03 | `IChannel` 接口至少包含：open/close/read/write/isConnected/getStats；串口/TCP/SocketCAN/周立功 CAN 均提供独立实现 |
| **SocketCAN 集成** | Linux 平台优先使用内核 SocketCAN（`can0` 网络接口），报文解析与 Modbus 帧解析共用协议引擎流程 | COMM-10、COMM-13 | 设计文档说明 SocketCAN 帧 ID 过滤、DLC 校验、CANopen / SAE J1939 预留解析扩展点 |

#### 7.5.2 数据库高并发写入（L2 历史库）

| 关注点 | 设计约束 | 对应 SRS 需求 | 设计验收检查项 |
|--------|---------|--------------|----------------|
| **SQLite WAL 模式** | 默认 SQLite 必须开启 WAL，避免写操作阻塞读取与采集线程 | NFR-PERF-12 | 初始化代码显式执行 `PRAGMA journal_mode=WAL;`；压测 5,000 点/秒持续 10 分钟无锁等待告警 |
| **批量写入策略** | 禁止逐条 INSERT；采用批量事务（如每 1000 条或每 100ms 一批）或内存缓冲 + 异步刷盘 | NFR-PERF-12 | 详细设计给出缓冲区大小、刷盘触发条件、异常退出时的数据保护机制 |
| **降采样与索引** | L2 历史库按 1s/5s 聚合落库；按测点 ID + 时间戳建立联合索引，保证 24h 查询 < 1s | FR-DLM-05 ~ FR-DLM-08、NFR-PERF-08 | 给出聚合算法（Max/Min/Avg/Count）与索引 DDL；查询性能基准测试通过 |

#### 7.5.3 Qt UI 渲染性能优化

| 关注点 | 设计约束 | 对应 SRS 需求 | 设计验收检查项 |
|--------|---------|--------------|----------------|
| **60 FPS 曲线滚动** | 同屏 ≥ 8 通道高频曲线时，不得使用全量重绘；须引入降采样绘制与局部刷新 | NFR-PERF-03、NFR-PERF-13 | 100ms 级数据在 1920×1080 画布上按像素密度降采样；滚动时 CPU 占用 < 15% |

#### 7.5.4 SBO 控制的安全边界

| 关注点 | 设计约束 | 对应 SRS 需求 | 设计验收检查项 |
|--------|---------|--------------|----------------|
| **Armed 状态超时** | SBO 的 Armed 倒计时（5s / 急停 3s）必须独立于通信轮询，使用独立定时器 | FR-CTRL-02、FR-CTRL-07 | 倒计时结束后无论通信状态如何都强制清除 Armed；无指令下发 |
| **断线自动清除** | Armed 状态下目标设备链路断线或响应超时，系统应自动清除 Armed 并提示失败 | FR-CTRL-07 | 故障注入测试：在 Armed 期间断开 TCP/串口，验证 UI 回到未选择状态并生成审计日志 |
